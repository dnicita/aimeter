- **Saldi in denaro (build 41, 2026-10-23)**: oltre alle quote in %, esistono DUE crediti distinti e l'app ora li mostra entrambi, etichettati: (a) **"Extra usage credits (Max)"** = i "Crediti di utilizzo" di claude.ai Settings → Utilizzo (EUR), con barra "% speso di quanto accreditato"; (b) **"API credits (Console)"** = il saldo di platform.claude.com → Billing (USD: acquistati + promozionali con scadenza). Entrambi via l'endpoint interno del Console `GET platform.claude.com/api/organizations/{org}/prepaid/credits` (stesso che usa la UI; scoperto in `arpan-ghosh/claude-spend-pulse`). **Non esiste via ufficiale**: l'Admin API ha solo usage/cost report ed è "unavailable for individual accounts" (verificato su `platform.claude.com/docs/en/api/admin.md`, 876 KB: zero endpoint di saldo). Sessioni separate: il `sessionKey` di claude.ai legge solo l'org Max (`billing_type=stripe_subscription`) e prende 403 sull'org Console (`billing_type=prepaid`); viceversa idem. Quindi (a) usa il cookie già presente, (b) un **secondo cookie "Console"** incollato dall'utente (pannello cookie, accetta anche il "Copy as cURL" di Safari), Keychain account `console_session_cookie`, org dal suo `lastActiveOrg`, keep-fresh Set-Cookie separato (`mergeCookies` condiviso). Verso platform si invia SOLO `sessionKey`. Settings: due righe "Show in menu bar" con soglia in valuta ("show if balance ≤ N EUR/USD"), chiavi `extra_credits_mode/thr`, `console_mode/thr`. Palette: Max-extra viola `#BF5AF2`/`#6E3FC2`, Console menta `#63E6BE`/`#0A8F6E`. Da fare se serve: `current_spend` (spesa periodo, risponde 200 col cookie Console).
- **Export per Claude Code (build 43)**: bottone "Copy for Claude Code" accanto a Refresh → negli appunti uno snapshot Markdown pensato per un LLM (importi `12.34 USD` con punto, date ISO, quote %, crediti Max e Console **tranche per tranche** con rimasto/concesso/scadenza/scope, promo separate). Lo stesso testo viene riscritto (atomico) a ogni fetch riuscito in `aimeter-snapshot.md`, cartella **selezionabile** in Settings ("Choose folder…"/"Default", chiave `snapshot_dir`; default `~/Library/Application Support/AIMeter/`), così si può metterlo dentro un progetto e una sessione Claude Code lo legge da sola con `cat` senza mai vedere i cookie. Modello: `CreditTranche`, `UsageManager.exportText()/writeSnapshotFile()/copyExportToClipboard()/chooseSnapshotDirectory()`.
- **Build rotta dalle CLT 27.0 (fix in build-local.sh)**: le Command Line Tools 27.0 (set. 2026) hanno SDK default macOS 27 dove `@State` di SwiftUI è una macro, ma il plugin `SwiftUIMacros` non è incluso → ogni `@State` fallisce, anche a HEAD. Lo script ora passa `-sdk MacOSX26.5.sdk` se presente (fallback al default). Se il 26.5 sparisce: installare Xcode o CLT con il plugin. Inoltre le CLT 27 non hanno più la slice x86_64 nelle lib statiche Swift (`libswiftCompatibility56.a`) → il link Intel fallisce: ora è facoltativo e l'app esce **arm64-only** (il Mac è Apple Silicon).

## ❌ Abbandonato — Monitorare credito API in dollari
Tentato (build 19) con WKWebView embedded + intercettazione XHR della pagina Billing del Console (per evitare di indovinare l'endpoint). **Bloccato**: l'account usa **login Google**, e Google **rifiuta l'OAuth nei browser embedded** ("Si è verificato un errore durante l'accesso"). Niente workaround affidabile (Safari protegge i cookie; spoof UA non basta). Anche il cookie di claude.ai NON autentica il Console (302→login) e claude.ai blocca curl (Cloudflare; l'app però passa). Unica via residua: cattura manuale cookie+endpoint del Console dal browser normale (manuale + da rifare a scadenza). Vista l'utenza quasi solo Max (crediti API ~fermi), **non vale la pena**. Codice rimosso in build 20.
